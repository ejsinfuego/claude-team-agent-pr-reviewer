# PR Reviewer

A server that watches configured GitHub repositories, detects pull requests needing review, and has Claude review them automatically.

## Language

**Watched Repository**:
A GitHub repository listed in `config.json` that the Poller monitors for pull requests.
_Avoid_: repo, project

**Pull Request (PR)**:
An open, non-draft pull request on a Watched Repository. Draft and closed/merged PRs are never candidates for review.
_Avoid_: MR, change

**Head SHA**:
The commit SHA at the tip of a PR's branch at a given point in time. A PR becomes eligible for review again whenever its Head SHA changes.
_Avoid_: latest commit, HEAD

**Review**:
A formal GitHub PR review (posted with event `COMMENT`, so it never blocks merging) generated by Claude from a PR's full context — diff, title/description, and existing comments — and posted by the Reviewer Script.
_Avoid_: comment, feedback

**Reviewed State**:
The fact that a specific (Watched Repository, PR, Head SHA) triple has had a Review successfully posted. Recorded in the Tracking Store only *after* the post succeeds — a failed post leaves the triple eligible again on the next poll.
_Avoid_: seen, processed

**Baseline**:
The one-time act of recording all of a Watched Repository's currently-open PRs as already having Reviewed State the moment the repository is first added — without generating a Review for any of them. Only PRs opened or updated after that point become eligible. See [ADR-0001](./docs/adr/0001-baseline-new-repos-instead-of-backfilling.md).
_Avoid_: backfill, seed

## Components

**Poller**:
The Node.js daemon. Reads `config.json` (Watched Repositories + poll interval), lists open PRs per repository via Octokit, checks the Tracking Store, and pushes newly-eligible (repo, PR, Head SHA) triples onto the Review Queue.

**Review Queue**:
The serial queue of eligible triples awaiting a Review. Processed one at a time — no concurrent Reviews.

**Reviewer Script**:
The self-contained bash script that performs one Review end-to-end: fetches a PR's full context via `gh`, invokes `claude -p` to generate the review text, and posts it via `gh`. The only place a Review actually happens.
_Avoid_: brain, worker

**Tracking Store**:
The SQLite database recording Reviewed State, keyed on (Watched Repository, PR number, Head SHA).
