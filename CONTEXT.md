# PR Reviewer

A server that watches configured GitHub repositories, detects pull requests needing review, and has Claude review them automatically.

## Language

**Watched Repository**:
A GitHub repository listed in `config.json` that the Poller monitors for pull requests.
_Avoid_: repo, project

**Pull Request (PR)**:
An open, non-draft pull request on a Watched Repository whose base branch is the Target Branch. Draft, closed/merged, and wrong-base PRs are never candidates for review.
_Avoid_: MR, change

**Target Branch**:
The single base branch name (e.g. `develop`), set globally in `config.json`, that a PR must target to be a candidate for review. PRs opened against any other base (e.g. `main`) are ignored entirely.
_Avoid_: base branch, integration branch

**Head SHA**:
The commit SHA at the tip of a PR's branch at a given point in time. A PR becomes eligible for review again whenever its Head SHA changes.
_Avoid_: latest commit, HEAD

**Review**:
A formal GitHub PR review (posted with event `COMMENT`, so it never blocks merging) consisting only of inline comments anchored to specific diff lines — no top-level summary body. Generated by Claude from a PR's full context (diff, title/description, existing comments) and posted by the Reviewer Script. If Claude finds nothing worth flagging, no Review is posted at all.
_Avoid_: comment, feedback

**Suggestion**:
An inline comment's optional one-line concrete code replacement, rendered by GitHub as a `suggestion` block with an Apply/commit button (the Copilot-style "change request" behavior) — same mechanism a human reviewer uses. Only included when the fix is a literal single-line replacement; feedback that isn't a direct line replacement (structural, multi-line, missing tests) stays plain-text with no Suggestion.
_Avoid_: fix, patch

**Reviewed State**:
The fact that a specific (Watched Repository, PR, Head SHA) triple has been through the Reviewer Script to completion — either a Review was successfully posted, or Claude found nothing worth flagging and none was posted. Recorded in the Tracking Store only *after* that outcome is reached; a failed run (script error, API failure) leaves the triple eligible again on the next poll.
_Avoid_: seen, processed

**Baseline**:
The one-time act of recording all of a Watched Repository's currently-open PRs as already having Reviewed State the moment the repository is first added — without generating a Review for any of them. Only PRs opened or updated after that point become eligible. See [ADR-0001](./docs/adr/0001-baseline-new-repos-instead-of-backfilling.md).
_Avoid_: backfill, seed

## Components

**Poller**:
The Node.js daemon. Reads `config.json` (Watched Repositories + poll interval + Target Branch), lists open PRs per repository via Octokit, filters to the Target Branch, checks the Tracking Store, and pushes newly-eligible (repo, PR, Head SHA) triples onto the Review Queue.

**Review Queue**:
The serial queue of eligible triples awaiting a Review. Processed one at a time — no concurrent Reviews.

**Reviewer Script**:
The self-contained bash script that performs one Review end-to-end: fetches a PR's full context via `gh`, invokes `claude -p` to generate inline comments anchored to diff lines, validates each comment's line against the actual diff, and posts the Review via the GitHub API. The only place a Review actually happens.
_Avoid_: brain, worker

**Tracking Store**:
The SQLite database recording Reviewed State, keyed on (Watched Repository, PR number, Head SHA).
